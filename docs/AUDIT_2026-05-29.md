# Jarvis Full-Stack Audit — 2026-05-29

Cross-platform audit of the Jarvis project (Android, macOS, Windows + shared/daemon).
Method: repository structure & architecture review, end-to-end flow tracing, and seven
parallel evidence-based deep-dives (Android speech, Android tool-routing, Android
memory/privacy, Android UI/platform, Mac daemon+app, Windows, build/CI/tests).
Every finding cites concrete `file:line` evidence. Unproven-but-likely items are
labelled **Risk**.

> Toolchain note: this audit ran on Linux with Java 21 + Gradle 9.4.1 only. `dotnet`,
> `swift`/`xcodebuild`, and the Android SDK were unavailable, so builds could not be
> executed here. The Android Gradle configure step was attempted and **failed** (AGP
> 9.2.1 unresolvable — see BLD-4). Build/test claims are therefore from static evidence.

---

## 1. Executive summary

**Overall release readiness: 3 / 10.** The product is feature-rich and the
architecture is thoughtfully documented, but it is **not releasable** on any platform
today. The blockers are not exotic: there is effectively **no CI** (workflows are in the
wrong directory), the **macOS app has no committed project and its test suite is inert**,
the **Android build is pinned to preview tooling that doesn't resolve**, **local-first is
silently disabled whenever a Mac is paired**, **barge-in resume is dead code**, and there
are several **plaintext-secret / PII-in-logs / backup-leak** privacy regressions that
contradict the project's own stated security invariants.

The good news: most individual subsystems are well-engineered (the local-first router,
tool guards, daemon DoS hardening, Windows redaction pipeline, Room migration chain).
The dominant failures are **wiring, ordering, and release-hygiene** problems, not deep
rewrites.

### Biggest 10 risks (confirmed)
1. **No CI runs at all** — both workflows live in `Android/.github/`; GitHub Actions only
   reads repo-root `.github/`. No build/lint/test gate on any platform. *(BLD-1)*
2. **Local-first is bypassed when paired** — Android forwards *every* transcript to the
   Mac and `continue`s, skipping all local tools, the confirmation gate, and the
   phone-capable guard. *(AND-ROUTE-1)*
3. **Plaintext Room DB (transcripts, name, home GPS, voice embeddings) is in cloud
   backup + device transfer.** *(AND-PRIV-1)*
4. **Barge-in resume is dead code** — the callback writes one object, the loop reads
   another; "go on"/corrections after an interruption never work. *(AND-SPEECH-1)*
5. **macOS test suite is inert** — 63/64 test files are not in any build target; daemon
   tests are hand-copied replicas that have already drifted from production. *(BLD-3 /
   MAC-5)*
6. **Gateway master token exposed via QR + clipboard**, violating the "no QR/token UI"
   invariant; Keychain ACL is world-open. *(MAC-1)*
7. **Windows browser-bridge WebSocket has no authentication** — any local process can
   inject browser context into the LLM/Mac (prompt-injection vector); the auth tests
   reference an API that no longer exists. *(WIN-1)*
8. **PII in logs in release builds** — Android logcat (message bodies, full numbers,
   addresses, exact GPS, raw transcripts); Mac logs transcript fragments. *(AND-PRIV-2 /
   MAC-6)*
9. **Spoken reminders/timers can silently fail** when backgrounded (mic-typed FGS started
   from a background broadcast is denied on Android 12+). *(AND-REL-1)*
10. **Conversation/audio recording has no consent, no retention, and is never deleted.**
    *(AND-PRIV-3)*

### Biggest 10 opportunities
1. Move CI to repo root and add per-platform jobs (Android/Windows/macOS) with path
   filters — instantly gates 3 large codebases.
2. Run the local gate *before* the Mac relay (or only relay genuinely non-local
   transcripts) — fixes latency, reliability, and "local tasks went to the cloud".
3. Make `local` the head of the LLM `.auto` chain (or default to `.localFirst`) — keeps
   prompt context on-device by default.
4. Wire partial-result early execution (`EarlyExecutionGate`/`TranscriptStability` already
   exist but are dead) — 200–600 ms latency win on common commands.
5. Make `BargeInDetector` mic-profile-aware + echo-aware — fixes both headphone
   under-trigger and speaker self-trigger.
6. Refresh Home Assistant vocab on the existing HA WebSocket events — kills recurring
   room/device mishears.
7. Route all LLM tool calls through `ToolDispatcher` — restores confirmation gating and
   the pending-message parking that fixes the WhatsApp re-ask loop.
8. Adopt a real crash backend (Firebase Crashlytics is one dep away on Android; Sentry
   covers all three) + structured diagnostic events.
9. Add Room `exportSchema=true` + migration tests and drop destructive fallback in
   release — removes silent total-data-loss risk.
10. Centralise redaction (Android log wrapper, Mac `privacy:` annotations, Windows title
    deny-list) and exclude the DB from backup — closes most privacy gaps at once.

## 4. Speech improvement plan (ordered)

1. **Fix barge-in ownership (AND-SPEECH-1).** Wire `BargeInDetector(onBargeIn = { handleBargeIn() })`
   to the runtime's own handler (which already builds `ResumableResponse`), or finish the
   `VoicePipeline` extraction so the stream buffers, `lastInterrupted`, and the loop share
   one object. Add a regression test that "go on" resumes.
2. **Make barge-in robust (AND-SPEECH-2).** Per-`MicProfile` `energyThreshold`/`holdMs`,
   reconfigured on headset change; add an echo-correlation / `lastSpokenText` guard and
   raise the speaker-output floor so TTS can't self-trigger. Keep the barge-in phrase fast
   path armed for the capture immediately following an interruption (AND-SPEECH, M2).
3. **Fix headphone VAD (AND-SPEECH-3).** Detect route via `AudioManager.getDevices(...)`
   (no `BLUETOOTH_CONNECT` needed); bias sensitivity generously when any headset is present;
   stop relying on deprecated `isWiredHeadsetOn`.
4. **First-token deadline (AND-SPEECH-5).** After `Thinking`, emit a short keepalive at
   ~2.5 s rather than waiting on the 30/60 s watchdog; actually consume or delete
   `bargeInFired`.
5. **Refresh HA vocab live (AND-SPEECH-4).** Call `HomeAssistantVocabRefresher.refresh`
   (debounced) from the HA WebSocket connect + on `haBaseUrl/haApiToken` change; add it to
   `promoteToFullAssistant()`; make `VocabularyBiaser.setRuntimeVocab` merge per-category.
6. **Thread real attention signals (AND-SPEECH-6).** Pass corrector confidence,
   last-reply timestamp, and `AudioManager.isMusicActive` into `AttentionSignals`.
7. **Wire partial-result early execution (AND-SPEECH-7).** Activate the dead
   `TranscriptStability`+`EarlyExecutionGate` for reversible commands; suppress duplicate
   dispatch on final. Re-tune phone `completeSilenceMs` to ~1.2–1.5 s.

## 5. Latency improvement plan (ranked by expected impact)

1. **Run the local gate before the Mac relay (AND-ROUTE-1).** Eliminates a full LAN
   round-trip (and the 8 s stall window) for on-device commands; biggest perceived win.
2. **Partial-result early execution (AND-SPEECH-7).** 200–600 ms on common reversible
   commands; the code already exists, just unwired.
3. **Re-tune end-of-speech silence (AND-SPEECH-7).** Phone `completeSilenceMs`
   2500→~1300 removes a visible end-of-turn hang.
4. **First-token keepalive (AND-SPEECH-5).** Converts "dead air" into perceived
   responsiveness on slow LLM starts.
5. **Local-first LLM chain (MAC-3).** Local model first avoids cloud RTT for fallback.
6. **Defer `JarvisApp.onCreate` work (AND-UI-1).** Faster cold start; removes ANR risk.
7. **Stop 1.5 s transcript polling + 30 fps amplitude (AND-UI-2, AND-UI-4).** Less main-thread
   churn → smoother UI.
8. **Debounce daemon `lastSeenAt` persistence (MAC-8).** Removes a synchronous disk write
   from the routing hot path.
